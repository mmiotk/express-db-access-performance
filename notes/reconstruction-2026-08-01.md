# Isolated reconstruction, 1 August 2026

Run by the author against a clean `git archive HEAD` export of the release commit, with no
database started and with `experiments/node_modules` symlinked from the working checkout
(dependencies are pinned by `package-lock.json`; the export carries the lockfile, not the
installed tree).

## What was checked

**Archived record integrity.** `sha256sum -c results/checksums.sha256` from inside the export:
**67 of 67 verified, 0 failed.** The manifest lists every tracked or explicitly unignored
`results/*.json` candidate; `scripts/release.sh --check` asserts that completeness separately, so
a dataset cannot ship unhashed.

**Table regeneration.** The documented no-database chain was run in full: `npm run tables:primary`,
every `table:*` script, and the five generators that sit outside those two groups
(`gen-rq2-leave-prisma-out`, `gen-rq2-multiplicity`, `gen-tost-closest`, `gen-fanout-table`,
`gen-protocol-chronology`), then `npm run sync:tables`.

Result, comparing the export's `paper/tables/` against the release tree:

| class | count | outcome |
|---|---|---|
| generator-backed, regenerated by the documented chain | 42 | **regenerated byte-for-byte** |
| generator-backed, not reachable without a database | 6 | **byte-compared unchanged** |
| authored analytical items, no generator | 10 | **byte-compared unchanged** |
| total in `paper/tables/` | 58 | |

Two distinctions matter and the manuscript must not blur either.

First, "regenerated" is not the same as "has a generator". Six generator-backed tables are not
reachable from the archive alone: S2 (`query_counts`) reads server statement logs that are not
archived, and S6 (`openloop`), S14 (`sameplan`), S19 (`waitevents`), S25 (`poolsize_mysql`) and
Figure~S2 (`fig_scaling`) have run-coupled renderers with no documented table-only path. They were
byte-compared unchanged, which is weaker evidence than regeneration and is reported as such.

Second, the class boundary is not the `% auto-generated by` header. `taillong.tex` (S23) and
`fig_p99_spread.tex` (Figure~S4) carry no header but are produced by `gen-tail.mjs` and
`gen-p99-spread.mjs` and do report measurements, so counting by header understates the
generator-backed set by two. The counts above were measured by recording which files the chain
actually wrote, not by reading headers.

`sync-tables` reported `48 unchanged, 0 updated, 10 authored paper-only, 0 refused`; its
"authored paper-only" figure of 10 is the correct one.

## What this does and does not establish

It establishes that the archived records are intact and that every measured value in the
manuscript can be rebuilt from them by committed code, on a machine with no database and no
access to the original campaign hosts.

It does not establish independent reproduction. The run was performed by the author, from the
author's own artifact, on the same machine family. Cross-host replication and third-party
reproduction remain unclaimed.
