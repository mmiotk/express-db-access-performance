# Decision log

**Purpose.** Append-only record of methodological and editorial choices, so that neither the
author nor the agent re-opens a settled question, and so reviewer responses can point at the
reasoning.
**Owner.** Author decides; agent records and never edits a past entry.
**Update when.** Any choice is made that a reviewer could reasonably challenge.

Format: one entry per decision, newest last. Never rewrite history; supersede instead.

## 2026-07-29 - RQ2 leave-Prisma-out sensitivity

- **Decision:** Report a leave-one-treatment-out repetition of the RQ2 reversal-promotion
  procedure, holding out Prisma (the only layer whose lower-level MySQL driver differs), and
  narrow the RQ2 claim accordingly.
- **Why:** All four promoted cross-stack reversals involve that one treatment, so a reviewer can
  ask whether the RQ2 finding is an artifact of the driver substitution. The analysis answers it
  from existing data instead of leaving it to assertion.
- **Result:** 4 promoted reversals with all seven layers, 0 with Prisma held out. Cross-stack rank
  agreement does *not* improve: deep fetch rises (0.86 -> 0.94) but aggregation falls
  (0.68 -> 0.54 primary, 0.64 -> 0.49 validation). Non-transfer is therefore not solely a Prisma
  artifact, but only the asymmetric treatment yields non-transfer that clears the promotion bar.
- **Affects:** `experiments/scripts/gen-rq2-leave-prisma-out.mjs` (new, generates
  `results/rq2-leave-prisma-out.json` and `tables/rq2_leave_prisma_out.tex`), Results RQ2,
  Discussion, Threats, abstract.
- **Not identified:** holding out Prisma removes the treatment and the driver substitution
  together; the contrast attributes the reversals to neither.

## 2026-07-29 - Table-ownership guard

- **Decision:** Guard the class of defect rather than patch its instances. Two scripts writing
  one table is now caught statically by `experiments/scripts/check-table-owners.mjs` (wired into
  `make release-check`) and refused at write time by `experiments/bench/table-owner.mjs`.
- **Why:** `durability.tex` was silently contested: `durability.mjs` wrote a different table to
  the same path and `\label` from a pre-state-fix record, and only ran-order kept the corrected
  version in the PDF. A sweep found the pattern was not unique.
- **Found by the sweep (4 contested tables, all still contested):**
  `interaction.tex` and `fig_insert_dispersion.tex` - owners read the accepted campaign, while
  `gen-r6-tables.mjs` writes both from superseded `raw.json` (results/tables copy only);
  `openloop.tex` - `openloop.mjs` versus owner `openloop2.mjs`;
  `canonicalization_cost.tex` - `canonicalization-cost.mjs` versus owner
  `gen-canonicalization-table.mjs`.
- **Not contested:** `cv_all.tex`, `cv_mysql.tex`, `resources_main.tex` are a producer/consumer
  pipeline (`gen-analysis-tables.mjs` spawns `bench/analyze.mjs` then reads its output) and are
  declared in `ALLOWED_SHARED`.
- **Resolved (2 of 4):** the superseded writes were deleted from `gen-r6-tables.mjs`. It no
  longer writes `interaction.tex` or `fig_insert_dispersion.tex`; both are produced only by
  their owners from the accepted campaign, and regenerating through those owners reproduces the
  committed tables byte-for-byte. The script keeps its Q6 ex-MikroORM rank print, which reads
  the superseded campaign by design because it describes that campaign, and now says so.
- **Resolved (3 of 4):** `openloop.mjs` no longer writes `openloop.tex`. It and `openloop2.mjs`
  measure the same estimand (constant-arrival tail on the deep fetch); `openloop2.mjs` applies
  the coordinated-omission correction and covers both engines, and its own header records that
  it "replaces the uncorrected run". The supplement caption for `tab:openloop` describes the
  corrected measurement, so an `openloop.mjs` run would have made the table contradict its own
  prose. `results/openloop.json` is still written for provenance.
- **Resolved (4 of 4):** `canonicalization_cost.tex` is a producer/regenerator pair, not
  supersession: `canonicalization-cost.mjs` runs the host-sensitive microbenchmark and archives
  it, `gen-canonicalization-table.mjs` rebuilds the table from that archive without re-running
  the timing. Declared in `ALLOWED_SHARED`. A real defect was found alongside it: the
  microbenchmark defaulted to `RAW_FILE=raw.json` (superseded) for its fastest-HTTP-p50
  comparison column, although the archived output demonstrably used `current-primary.json`
  (its column reads 7/12/13/6, matching current-primary, not raw's 6/12/12/6). Default
  corrected, and the source campaign is now recorded as `design.primary_source`.
- **Status:** the ownership guard passes (40 tables, no contested owners). Remaining
  `release-check` failures are ARTIFACT (uncommitted/untagged) and REPRODUCIBILITY (tables
  regenerated with updated captions vs the tagged release), both expected for in-progress work.
- **Stale-default hazard:** `bench/analyze.mjs` defaulted `RAW_FILE=raw.json` (superseded).
  Fixed to `current-primary.json`; regenerating the full table chain changes no committed table,
  confirming the default was never the path actually used.
- **`scripts/ci-tables.mjs` fixed too.** It generates the headline `deep_fetch.tex` /
  `write.tex` and defaulted to the superseded `raw.json`. Confirmed stale rather than
  intentional: the committed table carries `pg=3638` (current-primary), not `3687` (raw); the
  only invocation in `package.json` overrides the default; and the script has no
  compare-against-earlier-campaign semantics. After the fix a bare `node scripts/ci-tables.mjs`
  reproduces `deep_fetch.tex` byte-for-byte.
- **`scripts/utilization.mjs` fixed.** Here `RAW_FILE` supplies the CAPACITY DENOMINATOR, not a
  table: every offered rate is a fraction of each layer's deep-fetch throughput from that file, so
  a superseded denominator shifts the operating point itself. Confirmed stale rather than
  intentional: all 16 capacities recorded in the archived corrected runs match
  `current-primary.json` (0/8 PostgreSQL match `raw.json`). Default fixed; the run now also
  writes a provenance sidecar recording `primary_source`, engine, fractions, and reps.
  Separately verified that `r.rps` equals `median(rps_samples)` in all 18 deep-fetch cells, so
  the code's capacity proxy matches the manuscript's stated Chat-50 definition.
- **Pre-existing drift found:** `paper/tables/utilization.tex` and `utilization_mysql.tex` were
  stale against `gen-r4-tables.mjs`. Regenerating changed the CAPTION ONLY (no data row moved):
  the newer caption explains the min-max brackets already present in the cells and adds "with
  only five replicates the bracket is the raw spread, not an interval estimate". Kept, since the
  generator is the source of truth and the new text is more accurate.
- **Gap in the reproducibility gate:** `gen-r4-tables.mjs` is not in the `table:*` chain that
  `make release-check` regenerates, which is why this drift was invisible.
- **Drift sweep run (2026-07-29):** all 22 pure table generators were re-run against the archived
  data and their output compared by content hash. Result: no further drift. The only tables
  differing from HEAD are `rq2_cross_campaign` (caption edit, Stage 6) and `utilization` /
  `utilization_mysql` (caption regeneration). No data row changed anywhere. Sweep sensitivity was
  validated by perturbing a table and confirming detection; a first attempt that counted changed
  FILES rather than content was insufficient and was discarded.
- **`scripts/postreboot.mjs` checked and fixed, with a distinction.** Its baseline is frozen
  into the output: each row stores `primary_deep_rps` and `ratio`, and `gen-postreboot.mjs`
  renders those stored fields without re-reading any primary file. The archived
  `postreboot.json` (2026-07-17) is paired with `raw.json` 6/6 and with `current-primary.json`
  0/6, which is the CORRECT historical pairing: it was the prevailing campaign when the restart
  run was taken. So the committed table and the manuscript's "up to 16%" were never affected by
  the stale default (verified: max |ratio-1| = 15.9%). The default nevertheless governed FUTURE
  runs, where pairing a fresh restart measurement against a two-campaigns-old baseline would
  confound the restart effect with cross-campaign drift; changed to `current-primary.json`, with
  the frozen historical pairing documented in the header so it is not "corrected" later.
- **Closed, manuscript-side:** the 16% claim now names its baseline in both places. Threats reads
  "a post-restart rerun of six representative cells moved absolute throughput by up to 16%
  against the campaign prevailing when it ran, which is the superseded pilot rather than the
  accepted campaign, since the restart check preceded the latter." The generated
  `postreboot.tex` caption carried the same ambiguity ("against the primary median") and was
  fixed at its generator, so both statements agree. No number changed; max |ratio-1| = 15.9%. They are safe as orchestrated
  (`npm run tables:primary` passes `RAW_FILE=current-primary.json`) but unsafe if run bare.
  Deep-fetch medians differ between the campaigns by -0.6% to +2.3%, so a bare run would
  silently shift published numbers without any build error.

## 2026-07-29 - Reproducibility gate coverage

- **Decision:** Extend the `table:*` chain that `make release-check` regenerates from 5 to 18
  entries, covering every generator that can rebuild a table from archived data, and make
  `fig_cpu_tradeoff.tex` fully generated rather than patched in place.
- **Why:** the gate only checked tables it knew how to rebuild, so out-of-chain generators could
  drift undetected. `paper/tables/utilization*.tex` had in fact drifted (caption only, no data)
  and the gate could not see it. After the change the gate reports 6 changed files where it
  previously reported 2.
- **`fig_cpu_tradeoff.tex`:** `gen-tables.mjs` used to read the committed file and substitute only
  its `coordinates {...}` block, so the axis setup and caption existed nowhere but in that file.
  It could not be reconstructed from archived data, and a hand-edit to it survived regeneration
  silently. The generator now emits the whole figure (`String.raw`, since `\begin` is an escape
  in a template literal). Verified byte-identical to the committed content apart from the header,
  which now names the generator so the ownership guard applies; verified idempotent; and verified
  it rebuilds correctly after the file is destroyed, which was previously impossible.
- **Coverage measured empirically,** by marking every generated table and re-running the chain:
  35 of 46 are regenerated. The other 11 are live-measurement outputs (need running databases),
  authored analytical items per `MANIFEST.md`, or `query_counts.tex`, whose input is an
  unarchived transient. Coverage is therefore complete for everything reconstructible offline.
- **`sync:tables` hardened.** It was `cp results/tables/*.tex ../paper/tables/`, an
  unconditional copy: a generator writing straight to `paper/tables/` could have fresh output
  replaced by a stale `results/` copy. Replaced by `scripts/sync-tables.mjs`, which skips
  identical files, reports each file it updates, and REFUSES to overwrite a table whose
  `paper/` copy is newer than its `results/` copy (that ordering means `paper/` was written
  later, so copying would discard the fresher content); `SYNC_FORCE=1` overrides. Tables
  present only in `paper/tables` are authored items per `MANIFEST.md` and are left untouched.
- **Measured before fixing:** after running every chain generator, `paper/` and `results/`
  agreed on all 46 shared tables, so the hazard was structural rather than active. All three
  behaviours were tested: normal update copies and reports, the destructive ordering is refused
  with a non-zero exit, and `SYNC_FORCE=1` proceeds.

## 2026-07-30 - A drifted reference title caught by the ledger work

- **Finding:** `orm_compare_jcct_2025` carried the title "Comparing the Performance of Prisma,
  TypeORM, and Sequelize on PostgreSQL". The published title is **"Comparing the Performance of
  ORMs"**. The .bib title was an expanded, descriptive invention.
- **How it surfaced:** the entry failed Crossref, OpenAlex, and Semantic Scholar. Its DOI prefix
  10.14456 is registered with the Thai NRCT rather than Crossref, so index absence was structural

  (TCI ThaiJo), confirmed authors, journal, volume 3, issue 2, pages 201--213, and year 2025 --- six
  of seven fields matched exactly, and only the title did not.
- **Fixed:** title corrected in `references.bib`; recorded in the ledger as `publisher`-verified.
  The prose describing the study (four relation types; response time, memory, CPU) is accurate and
  was left unchanged, since the publisher page confirms it.
- **Why this matters:** this is precisely the fabrication class CLAUDE.md section 6 exists to catch,
  and it survived until the control file was actually populated. It is an argument for the ledger
