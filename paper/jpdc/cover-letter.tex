Dear Editors,

Please find enclosed the manuscript, "A Comparability Protocol for Benchmarking Relational Database Access Layers in Express.js," submitted as a Regular Paper to the Journal of Parallel and Distributed Computing.

\textbf{Fit to the journal.} The manuscript is a performance-analysis paper about a data-intensive server under concurrent load, and I state its relationship to the journal's scope plainly rather than stretching it. The system measured is a single-host Express.js service over PostgreSQL and MySQL, so the work contains no parallel algorithm and no multi-node deployment. What it does contribute to the journal's "performance analysis" and "data-intensive platforms and applications" areas is a measurement discipline for concurrent request-serving systems: it treats capacity and latency as distinct operating points, requires that reported tail latency be located with respect to saturation rather than to an arbitrary offered load, and shows empirically that the ranking of implementations at high load differs from their ranking at matched utilization. That distinction is a general hazard in throughput-and-tail reporting for concurrent systems, not a property of the access layers used to demonstrate it. If the editors judge the single-host scope to place the work outside the journal's remit, I would rather learn that at screening than occupy reviewer time.

\textbf{Contribution.} The paper proposes an executable protocol for deciding when two configured implementations are comparable for a stated estimand, and what their measurements license. It requires task-derived read checks, cross-implementation differential equivalence, post-write state validation, a predeclared configuration-selection policy, and separately located capacity and latency operating points. The protocol is exercised in one instantiation: nine policy-selected configurations and two tuned native references, across two engines and five access patterns, in a 25-run randomized-block campaign, with a reduced second campaign on the same host testing rank stability, and a single-rater audit applying the protocol's codebook to nine external benchmarks.

\textbf{What the results do and do not establish.} The widest measured spread is a deep fetch at 7.01x on PostgreSQL and 5.12x on MySQL; forcing the same SQL through raw facilities leaves 1.71x and 2.03x, which is a compound contrast and isolates no single mechanism. Four cross-stack rank reversals recur in both campaigns, all involving the one treatment whose MySQL driver differs, and the experiment does not identify the database engine as the cause. The protocol is offered as a candidate with one worked instantiation, not as a validated methodology. The paper supports no universal ranking of the libraries it measures and no estimate of their intrinsic overhead.

\textbf{Residual limitations, stated in the article.} All adapters and treatment assignments are single-author; both campaigns run on the same virtualized host; the external audit has one rater, so it demonstrates bounded application of the protocol rather than inter-rater reproducibility. Result-blind review packets ship with the artifact, but no unperformed review is counted as evidence: the recommended stage is reported as unsatisfied in both the compliance table and the machine-readable checklist, and the agreement scorer returns "not computable" while one rater is recorded.

\textbf{Reproducibility.} The artifact contains pinned dependencies, immutable documentation snapshots and hashes, exact source archives for both accepted campaigns, the seed oracle, the campaign-state validator, raw per-repetition measurements, a machine-readable protocol checklist, the external-audit dataset, and generators mapping every reported table and figure to its inputs. It is archived at Zenodo, concept DOI 10.5281/zenodo.21313858, which also carries an immutable per-version DOI. Author-run isolated reconstruction regenerates the reported tables byte-for-byte from archived data without starting either database; independent third-party reproduction has not occurred and is not claimed.

\textbf{Formatting.} The manuscript uses the Elsevier \texttt{elsarticle} class with numbered references, is 16 double-column pages including the reference list, and has a 250-word abstract. \texttt{supplement.pdf} is submitted as online supplementary material rather than as an embedded appendix.
